# I SEE YOU 电脑处理中心

## 0.17 当前默认：Omni Realtime

语音继续使用安卓已有的 `qwen3.8-omni-flash-realtime`；电脑画面分析、物品比较和补充意图理解也统一使用该 **Realtime** 型号。默认路径不调用 Jev、VL 或 `qwen3.8-omni-flash` 非实时模型。旧 Jev 适配器只保留用于历史回归检查。

电脑需设置 `DASHSCOPE_API_KEY`（也兼容 `QWEN_API_KEY`）。可复制 `.env.example` 为本机 `.env` 并填入，启动脚本只在当前进程读取；不要提交或发送 `.env`。默认官方 WebSocket 地址已经用本机账号验证；账号要求指定业务空间时，将 `ISEEYOU_OMNI_REALTIME_URL` 设为对应北京/新加坡 workspace 地址，程序固定模型参数为 realtime。

从 0.16 更新时先备份，替换电脑服务源文件，保留原 `runtime/`、`models/`、`.env` 与 Python 环境；不要清空用户记忆。此改动不需要重新安装平板 APK。端口、配对和 v2 备份格式不变。新版 `/health` 显示版本 0.17.0 及 realtime 模型名。

公开图片接口自检（会调用真实付费模型，不读取用户记忆）：`node --env-file-if-exists=.env scripts/omni-live-check.mjs`。本地检查：`npm test` 及 `python test/tracking_test.py`。实物流程见 [本轮验收说明](../docs/omni-realtime-0.17.md)。

以下保留迁移背景与旧版演进记录，其中 Jev 的分工描述适用于 0.16 及之前。

本目录以用户提供的方案 B 常驻 YOLO、最新帧入口和同帧裁剪为基础，接入现有安卓界面、受控记忆和原 Supabase 私有备份。安卓原有数据库保留；0.12 的任务与新记忆由电脑负责。

## Windows 运行

1. 安装 Node.js 24、Python 3.11。首次运行 `准备电脑环境.ps1`。
2. 运行 `启动电脑服务.ps1`，默认使用 CPU。无需先配置 Jev 或 Supabase 密钥。
3. 电脑与平板连接同一网络。在 `runtime/pairing-links.txt` 选择电脑实际 Wi-Fi 地址对应的一行，在应用原有“记录”输入 `连接电脑 ` 后粘贴该行。一次连接后应用加密保留，回到前台自动重连。
4. 如当前只通过 USB 调试连接，可对本应用使用 `adb reverse tcp:8765 tcp:8765` 并使用 127.0.0.1 对应的连接地址。该方式用于开发检查，拔掉 USB 后要重新配对实际局域网地址。

不要把连接文件发送给其他人。应用只在自己的连接中固定电脑证书，不要求往平板系统安装证书。不要向 Git 提交 `runtime`，其中有本机配对信息及个人记忆。

`-Device 0` 供另行安装并验证 CUDA 环境的电脑使用；不可用时明确失败，默认 CPU 不要求独立显卡。已验证版本与模型摘要见 `requirements-lock-cpu.txt` 和 `models/manifest.json`。模型只加载一次；输入不积压旧帧。

模型权重不随源码提交。首次从GitHub获取本分支后，请把已有交付包中的`yolo11s.pt`放到`pc-gateway/models/`；摘要需与`models/manifest.json`一致。准备脚本会检查模型，检测进程不会自动联网下载。

## 记忆与云端

首次连接时使用平板已有的登录，先从同一 Supabase 账号恢复，再导入平板旧记忆；同一编号选择较新记录。同名不同编号独立保留。以后新记忆由电脑保存，平板原数据作为迁移前副本保留，不进行双向同时写入。

“记住这个杯子”先落盘场景和时间，再并行调用千问描述与 Jev 独立核对。没有目标裁图也保留场景；位置和目标照片分项保存。只有实际保存结果进入显示和本机统一播报。查询读电脑记录；普通场景描述不写长期记忆。用户说“拿到了”后，不会继续把旧位置当作之后的去向。

0.14 增加同帧本地候选与千问目标范围，Jev 独立确认候选和位置；唯一候选的检查可与千问描述并行。复杂语句与普通问答改用纯文本意图接口，明确指令仍直接处理。场景回答取消三个物品上限，旧请求错误不再追加到新回答后面。处理状态只在界面显示，最终保存结果只播一次。云端视觉等待仍有约 5～9 秒的实测耗时，尚未完成流式播报优化。

0.15 在外观描述和相对位置已经写入后即可回答，Jev 独立复核随后补充，复核不确定不会丢失观察。无裁图时仍保留参考画面和描述。查询区分相机观察与核实位置，已有外观和位置分项汇总；“他/她”可指代当前物品。新安卓支持异步接收指令及自适应聊天宽度。更新服务与安卓后使用，原 v2 备份字段兼容。

Supabase 继续作为私有备份与恢复。没有改公开权限、增加管理员密钥、删除或覆盖已有云端快照。上传后重新下载核对；恢复只补缺失编号。兼容安卓 v1/v2 备份；电脑追加的拿取事件作为 v2 对象扩展字段，旧 0.11 安卓可恢复照片/位置/场景，但不会显示新拿取事件。0.12 前台从电脑读取完整记录。

平板已有的 OpenRouter Jev Key 和备份登录在固定电脑证书的连接中供当前服务使用，电脑只保存在进程内存，不写入数据库或备份。电脑更新登录令牌时，会回存平板的加密存储。实时语音仍复用安卓已验证的千问接入；电脑发起受控意图补充理解，固定图像描述由电脑调用现有千问接口。

0.13 的“新会话”会同步重置平板与电脑的临时上下文，停止当前采集和任务；物品记忆保留。平板聊天历史按消息保留 30 天，只供查看，不自动延续旧会话，也未加入物品云备份。旧版无日期聊天从升级日起保留 30 天。更新此功能时须同时更新安卓和电脑服务。

## 0.16 找物与追问修复

物品别称和颜色名称映射到同一候选类别；泛称有多件记录时保留歧义，不自动合并。历史位置查询不启动相机，明确询问当前位置才启动找物。YOLO候选先按已存粗略颜色特征排序（没有特征则按类别置信度），再由Jev对比参考照片；分数不能单独确认个人物品。失败后保留当前目标，过期结果说明为刚才的观察，错误阶段记录在本机runtime/diagnostics.jsonl，不记录现场图片或密钥。详见[修复与验收边界](../docs/cup-memory-fix-0.16.md)。

## 检查

```powershell
$env:ISEEYOU_PYTHON=(Resolve-Path '.venv/Scripts/python.exe').Path
npm test
node scripts/model-smoke.mjs
```

流程检查中的云服务使用模拟数据。模型检查使用仓库内的公共公交车图，检测进程禁止网络连接。这些不代替真实杯子连续语音验收。`scripts/interop-server.mjs` 是仅供本机安卓备份互通检查的模拟服务，使用 8767 端口。

## 复用来源

保留 `vendor/plan-b/SOURCE.json`、原许可与声明。复用手机最新帧入口和 MJPEG 解析；Python 检测服务沿用常驻进程与同帧裁剪设计，并增加多候选输出、统一图像方向及安卓兼容的外观描述数据。未照搬对方表单、三角度/手动地点登记或硬编码 ESP32 地址。
