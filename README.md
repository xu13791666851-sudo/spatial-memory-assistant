## 直接使用已上线的网页（推荐）

[打开空间记忆助手](https://spatial-memory-xuziyi.netlify.app/video/)

手机用 Safari 打开上述链接，电脑也可以用浏览器打开。无需登录或填写访问码。点击“开始对话”，允许摄像头和麦克风后即可尝试使用。

测试分支开启后仅播报问候，显示摄像头画面并等待提问，不自动描述第一张画面。用户说“眼前有什么”“描述一下周围”或“帮我找水杯”后才识别并回答，位置以镜头画面方向和可见物品为参照。摄像头默认观察5分钟后关闭，语音继续；“更多 → 观察选项”可选择5或10分钟。说“停止观察”可提前关闭摄像头；说“再看一下”“看看周围”或“帮我找水杯”可以重新观察，也可点击“重新观察”。原来的 `/memory` 链接会转到这个合并页面。

摄像头预览会先开启，和语音连接同时准备。本地预览目标为 24 帧／秒，上传仍保持低帧率。画面占据页面的主要空间，描述文字可滚动查看，底部并排保留“开始／结束”和“再听一遍”；“更多 → 连接与声音设置”可选择标准、大字或特大文字。

默认让环境描述、连续对话和“再听一遍”都使用千问声音。结束后点击“再听一遍”会重新连接语音，摄像头不会因此重新开启。可在设置中开启“加速模式：画面描述用手机声音”，图片理解生成完整句子后立即逐句朗读；加速模式会切换声音。网络、设备和云端处理仍会影响首次等待时间。

问当前画面中的物品时，获取新画面；在家直接问“杯子在哪”会先查询已保存的历史位置，并邀请用户拍摄该处确认。“帮我找杯子”“杯子现在在哪”先看新画面，没看到时再提供历史线索。摄像头关闭后不能把旧画面说成当前位置，确认当前位置需要重新观察。若目标被遮挡、画面模糊或有多件同类物品，助手应说明或追问；不估计厘米距离或伸手路线。

### 用户与画面人物

公网版的图片理解和实时对话共用 `web/person-context.mjs` 中的人物指代规则。用户可能在镜头后方或画面之外；画面中的人物默认身份未知。描述使用“画面中央的一位人”“左侧穿白衣服的人”，不能把对方的衣着、动作、手持物直接说成用户的。单人、前置摄像头、镜面、局部手部都不构成身份确认。

问“我手里拿着什么”不代表画面中的手一定属于用户。无法确认对应关系时，应简短说明，再描述可见内容。用户明确指定“左边穿白衣服的是我”时，只作为本轮用户提供的指代线索，不建立人脸档案，也不能在人物变化后继续猜测。转述与播报保留这一指代边界。

本次只调整模型描述规则，没有声纹验证、人脸识别或旁人语音过滤。规则不能保证模型永不出错，需要在预览版上做以下真机验收；现有离线测试不能证明真实模型识别准确率：

| 场景 | 提问 | 预期 |
| --- | --- | --- |
| 用户在镜头后，另一人拿杯子 | 眼前有什么？ | 描述“画面中的人拿着杯子”，不称其为“你” |
| 同一画面 | 我手里拿着什么？ | 说明无法确认哪位是用户，再描述可见持物 |
| 多人、镜面或前置摄像头 | 哪个是我？ | 不凭位置、人数或摄像头方向认定身份 |
| 只拍到一只手拿杯子 | 看到了什么？ | 描述“一只手拿着杯子”，不判断是谁的手 |
| 明确指代后换人或重新观察 | 左边穿白衣服的是我；再看一下 | 区分用户提供的线索与视觉确认，不将旧指代套到新人物 |

上述场景分别测试普通场景和家中场景，以及默认语音、加速播报和“再听一遍”。

### 可选：前台语音唤醒

### 普通场景与家中场景

页面默认是“普通场景”。开启摄像头后问“眼前有什么”，助手会先根据新画面给出简短描述；“它旁边是什么”会沿用本轮正在寻找的物品，再请求新画面。普通场景默认不使用家中记录；明确问“之前记住的杯子在哪”仍能查询历史位置，普通场景不写入家庭记忆。

在页面顶部把“当前场景”改成“家”，或在对话中说“我到家了”，即可使用家中物品记忆。用户说“记住，钥匙放在玄关桌上”，会直接保存所提供的位置；说“帮我记住这个蓝色玻璃杯的位置”，会拍摄新画面，只有目标唯一且位置有可见参照时才保存并回报，无须点击确认。说“记住它现在的位置”或“更新到这里”会重新拍摄当前目标再保存；其他修改或删除操作仍需要页面确认。重新打开网页时需要再次选择“家”。旧版浏览器中的物品记录仍可在“家”中查看。说“我出门了”可切回普通场景。

在家说“帮我找物品”时，助手先查看当前画面。如果明确没看到目标，会补充“上次记录在……”作为历史线索，并说明尚未确认现在仍在那里。看不到画面之外的区域不代表物品不在家。切换场景或关闭摄像头后，旧画面不能作为当前位置；只有明确的记住/更新口令才会改写位置；普通观察和寻找不会自动改写。

当前画面的简短结果可直接由浏览器播报，以减少等待实时语音助手再次生成回答的时间。不同浏览器的本地语音效果和真实响应时间仍需真机验证。

### 看图记忆与连续找物（本分支）

- “帮我记住这个蓝色玻璃杯的位置”开启一次最长 5 分钟的记录意图。新画面必须返回唯一目标、可靠位置及可见参照物，应用成功写入本机存储后才说“已记住”。画面不清或有多个目标时先补充信息，随后重新拍摄，不要求点击确认。
- “玻璃杯在哪”“刚才让你记住的杯子在哪”支持去掉“这个”等指示词和常见杯子称呼。多条记录均可能匹配时询问用户，不任选一条。匹配是保守的文字规则，尚非任意同义表达或物体重识别。
- 寻找期间，“已经对准了”“这样呢”“这里没有”“再看看”沿用目标并拍摄新画面。第一次没看到时给出历史位置；补拍仍没找到时，根据当前可见参照物询问补拍，或询问是否拿到其他地方，每次给出一个下一步。用户提供的线索不自动保存。
- 相似外观只表示候选物品，不能据此保证是同一件。历史位置不会变成当前位置；未知房间和材料不根据图片猜测。
- 取消、切换场景、暂停、关闭摄像头、断开连接或无关新问题会使待保存画面失效，延迟响应不能再写入。普通找物不创建长期记录。
- 记录沿用浏览器 `spatial-memory.records.v1`，兼容旧记录，保存文字位置、时间、来源及物品标识，不持久保存照片。预览网址和正式网址的存储彼此独立；更换浏览器、设备或清除站点数据后不会同步。

实现入口：`web/find-dialogue.mjs` 管理本轮目标、澄清和保存授权；`web/memory.mjs` 管理持久记录及名称匹配；`web/runtime.mjs` 连接语音、拍照与回执；`netlify/functions/vision.mjs` 返回结构化观察证据。模型不能直接写入本机存储。

真机验收步骤（需测试分支的预览地址，以下功能合并前不会出现在正式站）：

1. 在“家”中对准蓝色杯子及桌面，说“帮我记住这个蓝色玻璃杯的位置”，听到具体保存位置，记录列表应同步出现该物品。
2. 转向另一处，说“玻璃杯在哪”，应给出上次记录并提示尚未确认；按引导对准位置，说“这样呢”，应读取新画面。
3. 暂时拿走杯子，连续说“这里没有”“再看看”，应继续围绕同一目标沟通，不能认定仍在那里或无限重复同一句引导。
4. 对准两个相似杯子要求记住，应先问是哪一个；回答“左边那个”后重新取图，符合保存条件才回执。
5. 找到后说“记住它现在的位置”，应更新已选物品的记录；刷新并重新选择“家”，仍能查询。
6. 普通场景下明确问历史位置可读取；单纯观察不引用家庭记录。保存过程中取消或停止观察，不应出现迟到的保存。

自动测试覆盖状态和存储逻辑，使用模拟视觉结果；不能证明真实模型准确率、语音转写率或 iPhone 播报效果。

### 固定画面与连续对话记录（测试分支）

首页显示摄像头画面和最新回答，完整记录从“记录”入口展开；“放大画面”和“展开记录”只改变布局，不重新申请摄像头权限。底部在连接后提供暂停/继续、再听一遍和结束对话。大屏并排显示画面和最新回答，记录按需从侧边展开。文字输入在底部展开。

用户语音转写和助手回复按时间逐条保留，每条助手消息可单独重听。流式文本更新同一条消息，重播不增加重复消息。向上翻看或查看以前的对话时，新消息不会抢走当前位置；点击“有新消息”返回当前对话底部。来源标签只依据程序结果显示：真实写入成功为“已存入物品记忆”，历史查询为“历史位置 · 尚未确认”，新画面结果带观察时间。

文字记录按会话保存于当前浏览器 `spatial-conversations.v1`，刷新后可回看；不保存音视频，不自动成为物品记忆。下拉框选择以往会话，“删除”只删除选中的文字对话，不影响 `spatial-memory.records.v1` 中的位置。存储不可读或空间不足时明确提示，未保存的新文字仍留在当前页面。不同域名、设备、浏览器不共享记录；历史对话不会自动回灌到新一轮模型上下文。

检查：先 `node scripts/build-netlify.mjs`，再 `node --test tests/web.test.mjs tests/conversation.test.mjs`。安装 Playwright 和 Chrome 后可执行 `node tests/conversation-browser.cjs`，或用 `PLAYWRIGHT_MODULE` 指向现有 Playwright 包。浏览器测试对服务请求使用本地模拟，不请求摄像头/麦克风或云端模型；覆盖生成页面、去重、滚动、刷新、会话切换、删除，以及窄屏/键盘弹出/桌面尺寸。

## 已有功能

- 接入千问 `qwen3.8-omni-flash-realtime`，连续语音问答与打断。
- 自动描述与当前物品定位使用 `qwen3.6-flash` 对当前图片做一次视觉理解，默认由千问实时语音助手播报，也可选设备语音分句加速。画面理解结果只保存在本次会话中，不自动写入长期记忆。
- 公网页面本地预览采用正常帧率、云端上传保持低帧率，默认观察5分钟，可选择10分钟。结束或离开页面会关闭设备。
- 收到可用画面后自动请求环境描述；语音再观察后更新画面，不将旧画面当作当前位置。
- 物品相对位置使用镜头画面方向、可见参照物和摆放区域；当前观察与历史记忆分开回答。
- 可选的前台语音唤醒，浏览器不支持时可继续使用普通按钮。
- 摄像头预览铺满内容区，保留完整画面。
- 物品记录区分历史位置与当前观察；在家中说“记住，物品放在位置”会直接保存，其他修改和删除仍需确认。公网版保存到当前浏览器，本地版保存到电脑数据库。看图记忆与连续找物的新增流程仅接入公网版。
- 公网 HTTPS 入口，后台固定密钥，无需登录或填写访问码。
- 保留同一 Wi-Fi 下的 iPhone 本地 HTTPS 测试入口，供开发者选用。

实际物品识别准确度、iPhone 读屏、前台唤醒与不同设备上的连续语音体验仍需真机验证。NFC 真读取、房间地图、准确距离测量与自动发现目标提醒尚未实现。

## 开发者可选：电脑本地运行（与公网版不同）

```bash
python -m pip install -r requirements.txt
python src/run.py
```

打开 `http://127.0.0.1:8765/video`。**仅在这个本地版本中**，点击“更多 → 连接与声音设置”，填写自己的百炼业务空间 ID、对应地域和 API Key。本地密钥仅保存在当前程序运行的内存中，重启后需重新填写；这个限制不适用于公网版。

也可以先在语音记忆页面的文字入口试用本地记录，例如“记住，钥匙刚放在玄关桌上”“钥匙在哪”。本地指令只识别有限表达，自由语音表达需要连接千问。

## 管理者：Netlify 部署与后台配置

现有项目已部署并配置后台连接；普通体验者按前面的“直接使用已上线的网页”操作即可。以下说明用于另建部署或维护后台。

仓库新增了适合 Netlify 的构建与连接适配。导入本仓库后，使用构建命令 `node scripts/build-netlify.mjs`、发布目录 `dist`、函数目录 `netlify/functions`。也可以直接采用 `netlify.toml` 中的配置。

公网版本使用同一个页面和同一次会话处理观察、语音与记忆，无须切换功能页。使用浏览器 WebRTC 与千问持续通话，Netlify 函数负责后台连接检查和连接时的 SDP 转发，不承接长期 WebSocket。千问密钥保存在 Netlify 后台，网页不接收密钥。使用者无需登录或填写访问码。视频采用低帧率媒体轨道，而不是原来本地版的 JPEG WebSocket 上传；观察时间仍受页面与连接控制限制。

在 Netlify 的 Environment variables 中配置 `DASHSCOPE_API_KEY`、`DASHSCOPE_WORKSPACE_ID`、`DASHSCOPE_REGION`（`beijing` 或 `singapore`）。将密钥标为 Contains secret values；不要放入源码、网页或配置文件。变更后重新部署，让函数读取最新值。正式版与测试版需要分别确认相应部署环境中的配置，函数须能读取这些变量。缺少千问后台配置时不会调用模型。旧的 `APP_ACCESS_CODE` 已不再读取，可从后台删除；保留同源检查、请求格式校验、调用频率和会话时长限制。

物品记忆保存在当前浏览器，不与电脑 SQLite 数据库同步，也不与其他访问者共享。只有查询时才把相关记录提供给千问；家中“记住”口令直接保存，其他修改和删除仍需确认。iPhone 使用 Safari 打开 Netlify 的 HTTPS 地址后，无须安装本地测试证书。

```bash
node scripts/build-netlify.mjs
node --test tests/web.test.mjs
```

浏览器媒体权限、网络到千问的连通性及模型准确度仍须实际设备验证。Netlify 和百炼的用量及额度以各自控制台为准。

## GitHub 与其他托管方式

GitHub 仓库用于保存和分享程序。GitHub Pages 只能托管静态网页，不能运行本项目的 Python 后端和实时语音转发服务，因此仅上传代码不会得到完整可用的在线语音视频产品。

原始 Python 后端如需部署到其他平台，需要支持 HTTPS、WebSocket 和访问保护的服务器；不能直接把本机测试服务公开到互联网。上述 Netlify 适配采用不同的连接方式，密钥只留在后台，每位访问者的记忆保存在各自浏览器中。
