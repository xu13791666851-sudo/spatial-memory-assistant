# 空间记忆助手

面向视障用户的实验原型。公网版已把视频理解、连续语音对话和物品记忆合并到同一个页面，主要操作是“开始对话／结束对话”和“再听一遍”。可以在同一次对话中识别物品，记录用户明确提供的位置，再查询历史记录。

## 直接使用已上线的网页（推荐）

[打开空间记忆助手](https://spatial-memory-xuziyi.netlify.app/video/)

手机用 Safari 打开上述链接，电脑也可以用浏览器打开。无需登录或填写访问码。点击“开始对话”，允许摄像头和麦克风后即可尝试使用。

点击开始后，助手先简短介绍，摄像头显示本地预览，等待用户调整方向。不会自动截取第一张画面识别或播报。用户问“眼前有什么”“水杯在哪里”后，才截取当时的新画面并回答；闲聊和问候不触发看图。若唤醒时已经说“小忆，找水杯”，则直接处理找物请求，不额外播放介绍。位置以镜头画面方向和可见物品为参照。摄像头默认开启 5 分钟后关闭，语音继续；“更多 → 观察选项”可选择 5 或 10 分钟。说“停止观察”可提前关闭摄像头；说“再看一下”“看看周围”或“帮我找水杯”可以重新观察，也可点击“再观察一次”。原来的 `/memory` 链接会转到这个合并页面。

摄像头预览会先开启，和语音连接同时准备。本地预览目标为 24 帧／秒，每次需要观察时只截取一张图片上传识别；实时语音连接不再同时上传连续视频。画面占据页面的主要空间，描述文字可滚动查看，底部并排保留“开始／结束”和“再听一遍”；“更多 → 连接与声音设置”可选择标准、大字或特大文字。

当前测试版默认让环境描述、连续对话和“再听一遍”都使用手机或浏览器的中文朗读。千问仍负责语音识别、对话和图片理解，实时连接只请求文字输出，不生成播报音频；完整句子生成后即可由设备朗读。结束对话后的重播直接读取已有文字，不重新连接千问。不同手机的声音可能不同；这项修改不能消除网络和图片识别本身的等待。

在“更多 → 连接与声音设置”取消“使用手机声音：描述、对话和重播”，可以切回千问声音。声音选项需在结束对话后切换，避免同一次会话混用两种声音。没有设备朗读功能的浏览器会说明并使用千问声音；设备朗读中途失败时保留文字并提示重试，不会悄悄切换声音。开启读屏模式时继续由读屏播报。

问当前画面中的物品时，优先看当前画面；问“之前记录的钥匙在哪里”才查询历史记忆。摄像头关闭后不能把旧画面说成当前位置，确认当前位置需要重新观察。若目标被遮挡、画面模糊或有多件同类物品，助手应说明或追问；不估计厘米距离或伸手路线。

### 手机识别等待与排查

图片识别通过独立接口完成，语音连接只传声音，避免手机重复编码和上传视频。图片识别不等待旧语音响应或取消回执；常见的“眼前有什么”“我手里拿着什么”直接请求新画面，省去一次让语音模型决定调用工具的过程。普通环境概括在加速模式下可逐句播报；找具体目标仍等待结构化结果，以保留目标可见性和家中历史位置的判断。

页面先显示“正在识别当前画面”，完成后显示“识别用时 N 秒（含网络等待）”。该时间从截图到识别结果完整返回，包含图片上传、服务处理和网络等待；不包括最初建立语音连接、用户语音转写和后续语音播报，不能当作端到端响应时间，也不能单凭它判断是模型还是网络慢。

默认设备朗读会省去画面回答的第二次云端语音生成，普通对话也使用实时返回的文字逐句朗读。切回千问声音时，完整画面回答随朗读请求一并发送，不再等待画面上下文的更新回执；需要上下文的其他回答在回执等待超时后继续发送，不再被静默丢弃。声音开关不改变识别模型。

手机验收建议在同一网络、同一场景下对比手机声音与千问声音，分别记录：开始到预览出现、提问结束到文字出现、文字出现到开始播报。同时测试连续追问、打断、停止摄像头，以及家中“没看到目标”时的历史位置提示。离线检查只能验证数据路径和生命周期，尚无 iPhone 真机速度提升数据。

### 用户与画面人物

公网版的图片理解和实时对话共用 `web/person-context.mjs` 中的人物指代规则。用户可能在镜头后方或画面之外；画面中的人物默认身份未知。描述使用“画面中央的一位人”“左侧穿白衣服的人”，不能把对方的衣着、动作、手持物直接说成用户的。单人、前置摄像头、镜面、局部手部都不构成身份确认。

问“我手里拿着什么”不代表画面中的手一定属于用户。无法确认对应关系时，应简短说明，再描述可见内容。用户明确指定“左边穿白衣服的是我”时，只作为本轮用户提供的指代线索，不建立人脸档案，也不能在人物变化后继续猜测。转述与播报保留这一指代边界。

本次只调整模型描述规则，没有声纹验证、人脸识别或旁人语音过滤。规则不能保证模型永不出错，需要在预览版上做以下真机验收；现有离线测试不能证明真实模型识别准确率：

| 场景 | 提问 | 预期 |
| --- | --- | --- |
| 用户在镜头后，另一人拿杯子 | 眼前有什么？ | 描述“画面中的人拿着杯子”，不称其为“你” |
| 同一画面 | 我手里拿着什么？ | 说明无法确认哪位是用户，再描述可见持物 |
| 多人、镜面或前置摄像头 | 哪个是我？ | 不凭位置、人数或摄像头方向认定身份 |
| 只拍到一只手拿杯子 | 看到了什么？ | 描述“一只手拿着杯子”，不判断是谁的手 |
| 明确指代后换人或重新观察 | 左边穿白衣服的是我；再看一下 | 区分用户提供的线索与视觉确认，不将旧指代套到新人物 |

上述场景分别测试普通场景和家中场景，以及默认语音、加速播报和“再听一遍”。

### 可选：前台语音唤醒

在“更多 → 语音唤醒入口”中点击“启用语音唤醒（前台）”，完成浏览器授权后说“小忆”开始对话并听介绍，或直接说“小忆，找水杯”。结束对话后回到唤醒待机；点击“关闭语音唤醒”才停止待机监听。

此入口使用浏览器提供的语音识别，可能使用系统或在线服务；待机不建立千问会话。只在网页保持前台时工作，锁屏或离开网页会关闭唤醒。不支持或授权失败时保留“开始对话”按钮。不同 Safari／iPhone 的语音识别支持情况和真实唤醒效果仍需真机验证；建议用 Safari 打开，微信内置浏览器不作为本轮测试入口。

**公网版的 API Key 已固定保存在 Netlify 后台，使用者不需要填写 API Key、业务空间 ID 或地域。** 公网版已取消访问码，任何拿到链接的人都可以使用，产生的模型用量计入项目管理者的账户。

体验公网版不需要安装 Python、启动电脑服务、连接同一 Wi-Fi 或安装本地证书。分享产品体验时发送上述网页链接；本 GitHub 链接用于查看和下载代码。

公网版的物品记忆只保存在当前浏览器中，不与其他人的浏览器共享，也不与本地电脑版同步。清除浏览器数据会删除这些记录。

### 普通场景与家中场景

页面默认是“普通场景”。开启摄像头后问“眼前有什么”，助手会先根据新画面给出简短描述；“它旁边是什么”会沿用本轮正在寻找的物品，再请求新画面。普通场景不会读取或修改家中物品记录。

在页面顶部把“当前场景”改成“家”，或在对话中说“我到家了”，即可使用家中物品记忆。用户说出“记住，钥匙放在玄关桌上”这样的明确名称和位置，会直接保存并回报；说“记住这个”时先确认对象。其他修改或删除可口头说“确认／取消”，也可使用页面按钮。重新打开网页时需要再次选择“家”。旧版浏览器中的物品记录仍可在“家”中查看。说“我出门了”可切回普通场景。

在家找物品时，助手先查看当前画面。明确没看到正在找的已登记物品时，先问是否想听上次记录的位置；答应后才提供历史位置和时间，不能当作当前确认。对清楚可见、带可用参照位置的相近物品，最多提出一个身份核实问题；用户确认是之前那件后，再问是否更新位置，第二次确认才保存。画面过期、关闭摄像头、多件相似物品或用户否认时不自动更新。切换到普通场景不读取家中记录。

忘记名称可以说“我记过什么”“我忘记之前记住的什么物品了”，每次列出最多五个候选，支持“下一批”“第一个”和名称选择。支持常见别称、颜色片段与名称相近匹配，例如“装耳机的盒子”查找“白色耳机盒”；这不是任意描述都能准确对应个人物品。相近匹配需要用户确认，不自动合并名称。记录仍保存在当前浏览器，未增加跨设备同步。

测试版继续使用千问 `qwen3.6-flash` 看图、`qwen3.8-omni-flash-realtime` 对话。拍摄目标分辨率提高到 1280×720，按比例保留完整画面，图片最长边不超过 1280；JPEG 根据大小调整压缩。识别按区域检查清楚可见物品，结构化清单最多20项，回答不再限制为80字或5件物品。小物件、反光、遮挡和模糊仍可能识别错误或遗漏，不能把功能检查当作真实场景准确率证明。

观察选项默认5分钟，可选10分钟。观察计时不等于持续上传或实时跟踪：仍只在用户请求看图时上传快照，在完成该轮观察后提出必要的后续问题；不会空闲时反复发问。实时对话本轮上限为15分钟，为10分钟观察和开始前连接留出余量。

当前画面的简短结果可直接由浏览器播报，以减少等待实时语音助手再次生成回答的时间。不同浏览器的本地语音效果和真实响应时间仍需真机验证。

## 已有功能

- 接入千问 `qwen3.8-omni-flash-realtime`，连续语音问答与打断。
- 开场先介绍并等待提问；用户请求环境描述与当前物品定位后，使用 `qwen3.6-flash` 对当次新图片做一次视觉理解，测试版默认用设备声音播报，也可切回千问声音。画面理解结果只保存在本次会话中，不自动写入长期记忆。
- 公网页面本地预览采用正常帧率，每次观察上传单张图片，语音连接不重复上传视频；默认观察 2 分钟，可选择 1 或 5 分钟。结束或离开页面会关闭设备。
- 摄像头开启时仅预览，用户要求看图后才识别和播报；再次观察时更新画面，不将旧画面当作当前位置。
- 物品相对位置使用镜头画面方向、可见参照物和摆放区域；当前观察与历史记忆分开回答。
- 可选的前台语音唤醒，浏览器不支持时可继续使用普通按钮。
- 摄像头预览铺满内容区，保留完整画面。
- 物品记录区分历史位置与当前观察；在家中说“记住，物品放在位置”会直接保存，其他修改和删除可用语音确认或取消。公网版保存到当前浏览器，本地版保存到电脑数据库。
- 公网 HTTPS 入口，后台固定密钥，无需登录或填写访问码。
- 保留同一 Wi-Fi 下的 iPhone 本地 HTTPS 测试入口，供开发者选用。

实际物品识别准确度、iPhone 读屏、前台唤醒与不同设备上的连续语音体验仍需真机验证。NFC 真读取、房间地图、准确距离测量与自动发现目标提醒尚未实现。

## 开发者可选：电脑本地运行（与公网版不同）

下面启动的是独立的本地 Python 版本，仍保留“视频理解”和“语音记忆”两个页面，以及手动填写连接信息的方式。如果只是体验合并后的产品，请直接打开前面的公网链接，跳过本节。

需要 Python 3.11 或以上。

```bash
python -m pip install -r requirements.txt
python src/run.py
```

打开 `http://127.0.0.1:8765/video`。**仅在这个本地版本中**，点击“更多 → 连接与声音设置”，填写自己的百炼业务空间 ID、对应地域和 API Key。本地密钥仅保存在当前程序运行的内存中，重启后需重新填写；这个限制不适用于公网版。

也可以先在语音记忆页面的文字入口试用本地记录，例如“记住，钥匙刚放在玄关桌上”“钥匙在哪”。本地指令只识别有限表达，自由语音表达需要连接千问。

## 开发者可选：iPhone 本地测试

本节仅适用于从电脑启动的本地测试版。使用已上线的 Netlify 网页时，无须进行这些设置。

```bash
python -m pip install -r requirements-mobile.txt
```

手机与电脑须在同一 Wi-Fi。启动窗口显示手机设置入口、实际 HTTPS 网页和六位访问码；`outputs/手机访问/` 中生成二维码及说明网页。

证书只覆盖指定的局域网 IP，有效期 30 天。根证书的签发私钥不会保存。手机服务只有配对后才能访问配置、记忆或语音通道。网络隔离或防火墙可能阻止局域网连接；程序不会修改系统防火墙或证书信任。

## 管理者：Netlify 部署与后台配置

现有项目已部署并配置后台连接；普通体验者按前面的“直接使用已上线的网页”操作即可。以下说明用于另建部署或维护后台。

仓库新增了适合 Netlify 的构建与连接适配。导入本仓库后，使用构建命令 `node scripts/build-netlify.mjs`、发布目录 `dist`、函数目录 `netlify/functions`。也可以直接采用 `netlify.toml` 中的配置。

公网版本使用同一个页面和同一次会话处理观察、语音与记忆，无须切换功能页。使用浏览器 WebRTC 与千问持续通话，Netlify 函数负责后台连接检查和连接时的 SDP 转发，不承接长期 WebSocket。千问密钥保存在 Netlify 后台，网页不接收密钥。使用者无需登录或填写访问码。实时通话只传音频；观察时通过独立图片接口上传单张 JPEG，不重复传输视频轨道。观察时间仍受页面与连接控制限制。

在 Netlify 的 Environment variables 中配置 `DASHSCOPE_API_KEY`、`DASHSCOPE_WORKSPACE_ID`、`DASHSCOPE_REGION`（`beijing` 或 `singapore`）。将密钥标为 Contains secret values；不要放入源码、网页或配置文件。变更后重新部署，让函数读取最新值。正式版与测试版需要分别确认相应部署环境中的配置，函数须能读取这些变量。缺少千问后台配置时不会调用模型。旧的 `APP_ACCESS_CODE` 已不再读取，可从后台删除；保留同源检查、请求格式校验、调用频率和会话时长限制。

物品记忆保存在当前浏览器，不与电脑 SQLite 数据库同步，也不与其他访问者共享。只有查询时才把相关记录提供给千问；家中“记住”口令直接保存，其他修改和删除可用语音确认或取消。iPhone 使用 Safari 打开 Netlify 的 HTTPS 地址后，无须安装本地测试证书。

```bash
node scripts/build-netlify.mjs
node --test tests/web.test.mjs
```

浏览器媒体权限、网络到千问的连通性及模型准确度仍须实际设备验证。Netlify 和百炼的用量及额度以各自控制台为准。

## GitHub 与其他托管方式

GitHub 仓库用于保存和分享程序。GitHub Pages 只能托管静态网页，不能运行本项目的 Python 后端和实时语音转发服务，因此仅上传代码不会得到完整可用的在线语音视频产品。

原始 Python 后端如需部署到其他平台，需要支持 HTTPS、WebSocket 和访问保护的服务器；不能直接把本机测试服务公开到互联网。上述 Netlify 适配采用不同的连接方式，密钥只留在后台，每位访问者的记忆保存在各自浏览器中。

## 多参照记忆与声音一致性（2026-10-18）

当前网页的长期记忆依然保存在同一浏览器中，不会自动跨正式版、测试版或设备同步。旧记录继续兼容，历史数据无法凭空补回当时没有保存的细节。

新版记录可保存名称、外观、别称、主要放置区域、多个参照关系、保存时间和信息来源。用户要求从画面记住物品时，程序获取新快照，千问看图返回完整物品清单和关系，再由千问记忆整理接口结合用户原话与已有记录提出保存草稿。朗读草稿，用户说“确认”或点击确认后，才一次性保存。说“补充它在电脑左侧”可以保留同次摆放的其他参照；物品移动到新地方时旧位置关系不继续沿用，外观与别称保留。

看图模式固定使用结构化返回，两种声音共用同一份输入和结果，手机声音不会走丢失物品清单的纯文字通道。千问声音以逐字朗读请求播放已经生成的回答，其回传文字不替换原始观察或执行记忆工具。云端声音仍由生成模型朗读，不能保证任意文字都绝对逐字一致，不应把声音自然程度当作识别准确率。

查找个人登记名称时，只把名称、别称和外观提供给视觉模型，不提供旧位置，减少历史线索污染当前判断。若清单中已有匹配的类别或别称却返回“未看到”，应用改为疑似目标并询问特征，不自动认定个人身份。“明明在画面里”“你看漏了”等纠正会请求新画面。真实物品识别仍可能出错，需要真机检查。

记忆接口使用 qwen3.6-flash 整理自然表达和多参照草稿；识图继续使用 qwen3.6-flash，实时语音使用 qwen3.8-omni-flash-realtime。固定确认、保存失败和过期处理由应用执行，不由模型自行声称写入。默认观察5分钟、可选10分钟与独立IPv4语音连接保留。
