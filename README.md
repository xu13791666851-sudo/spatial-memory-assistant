# 空间记忆助手

面向视障用户的实验原型。公网版已把视频理解、连续语音对话和物品记忆合并到同一个页面，主要操作是“开始对话／结束对话”和“再听一遍”。可以在同一次对话中识别物品，记录用户明确提供的位置，再查询历史记录。

## 直接使用已上线的网页（推荐）

[打开空间记忆助手](https://spatial-memory-xuziyi.netlify.app/video/)

手机用 Safari 打开上述链接，电脑也可以用浏览器打开。首次使用，在“更多 → 连接与声音设置”中填写项目管理者提供的访问码并连接，再点击“开始对话”，允许摄像头和麦克风后即可尝试使用。

开启后，助手会等待可用画面，自动描述主要物品及相对位置并播报。随后可问“水杯在哪里”，位置以镜头画面方向和可见物品为参照。摄像头默认观察 2 分钟后关闭，语音继续；“更多 → 观察选项”可选择 1、2 或 5 分钟。说“停止观察”可提前关闭摄像头；说“再看一下”“看看周围”或“帮我找水杯”可以重新观察，也可点击“再观察一次”。原来的 `/memory` 链接会转到这个合并页面。

问当前画面中的物品时，优先看当前画面；问“之前记录的钥匙在哪里”才查询历史记忆。摄像头关闭后不能把旧画面说成当前位置，确认当前位置需要重新观察。若目标被遮挡、画面模糊或有多件同类物品，助手应说明或追问；不估计厘米距离或伸手路线。

### 可选：前台语音唤醒

在“更多 → 语音唤醒入口”中点击“启用语音唤醒（前台）”，完成浏览器授权后说“小忆”开始观察，或说“小忆，找水杯”。结束对话后回到唤醒待机；点击“关闭语音唤醒”才停止待机监听。

此入口使用浏览器提供的语音识别，可能使用系统或在线服务；待机不建立千问会话。只在网页保持前台时工作，锁屏、离开网页或退出访问会关闭唤醒。不支持或授权失败时保留“开始对话”按钮。不同 Safari／iPhone 的语音识别支持情况和真实唤醒效果仍需真机验证；建议用 Safari 打开，微信内置浏览器不作为本轮测试入口。

**公网版的 API Key 已固定保存在 Netlify 后台，使用者不需要填写 API Key、业务空间 ID 或地域。** 同一浏览器通常可记住验证 30 天；清除浏览器数据、主动退出设备或管理员更换密钥／访问码后需要重新验证。访问码不会公开在本仓库中。

体验公网版不需要安装 Python、启动电脑服务、连接同一 Wi-Fi 或安装本地证书。分享产品体验时发送上述网页链接；本 GitHub 链接用于查看和下载代码。

公网版的物品记忆只保存在当前浏览器中，不与其他人的浏览器共享，也不与本地电脑版同步。清除浏览器数据会删除这些记录。

## 已有功能

- 接入千问 `qwen3.8-omni-flash-realtime`，连续语音问答与打断。
- 自动描述与当前物品定位使用 `qwen3.6-flash` 对当前图片做一次视觉理解，再由实时语音助手播报。画面理解结果只保存在本次会话中，不自动写入长期记忆。
- 公网页面以低帧率观察画面，默认观察 2 分钟，可选择 1 或 5 分钟。结束或离开页面会关闭设备。
- 收到可用画面后自动请求环境描述；语音再观察后更新画面，不将旧画面当作当前位置。
- 物品相对位置使用镜头画面方向、可见参照物和摆放区域；当前观察与历史记忆分开回答。
- 可选的前台语音唤醒，浏览器不支持时可继续使用普通按钮。
- 摄像头预览铺满内容区，保留完整画面。
- 物品记录区分历史位置与当前观察；新增、修改和删除需要确认。公网版保存到当前浏览器，本地版保存到电脑数据库。
- 公网 HTTPS 入口，后台固定密钥，首次验证访问码后可记住设备。
- 保留同一 Wi-Fi 下的 iPhone 本地 HTTPS 测试入口，供开发者选用。

实际物品识别准确度、iPhone 读屏、前台唤醒与不同设备上的连续语音体验仍需真机验证。NFC 真读取、房间地图、准确距离测量与自动发现目标提醒尚未实现。

## 开发者可选：电脑本地运行（与公网版不同）

下面启动的是独立的本地 Python 版本，仍保留“视频理解”和“语音记忆”两个页面，以及手动填写连接信息的方式。如果只是体验合并后的产品，请直接打开前面的公网链接，跳过本节。

需要 Python 3.11 或以上。

```bash
python -m pip install -r requirements.txt
python src/run.py
```

打开 `http://127.0.0.1:8765/video`。**仅在这个本地版本中**，点击“更多 → 连接与声音设置”，填写自己的百炼业务空间 ID、对应地域和 API Key。本地密钥仅保存在当前程序运行的内存中，重启后需重新填写；这个限制不适用于公网版。

也可以先在语音记忆页面的文字入口试用本地记录，例如“记住，钥匙刚放在玄关桌上”“钥匙在哪”。本地指令只识别有限表达，自由语音表达需要连接千问。

## 开发者可选：iPhone 本地测试

本节仅适用于从电脑启动的本地测试版。使用已上线的 Netlify 网页时，无须进行这些设置。

```bash
python -m pip install -r requirements-mobile.txt
python src/run_mobile.py --host 你的电脑WiFi的IPv4地址
```

手机与电脑须在同一 Wi-Fi。启动窗口显示手机设置入口、实际 HTTPS 网页和六位访问码；`outputs/手机访问/` 中生成二维码及说明网页。

在 iPhone Safari 打开设置入口，按说明安装并手动信任本地测试证书，然后打开 HTTPS 网页并输入访问码。证书安装与信任必须由设备所有者自己完成。测试后可移除描述文件。电脑上的原有入口仍可独立运行。

证书只覆盖指定的局域网 IP，有效期 30 天。根证书的签发私钥不会保存。手机服务只有配对后才能访问配置、记忆或语音通道。网络隔离或防火墙可能阻止局域网连接；程序不会修改系统防火墙或证书信任。

## 管理者：Netlify 部署与后台配置

现有项目已部署并配置后台连接；普通体验者按前面的“直接使用已上线的网页”操作即可。以下说明用于另建部署或维护后台。

仓库新增了适合 Netlify 的构建与连接适配。导入本仓库后，使用构建命令 `node scripts/build-netlify.mjs`、发布目录 `dist`、函数目录 `netlify/functions`。也可以直接采用 `netlify.toml` 中的配置。

公网版本使用同一个页面和同一次会话处理观察、语音与记忆，无须切换功能页。使用浏览器 WebRTC 与千问持续通话，Netlify 函数负责访问授权和连接时的 SDP 转发，不承接长期 WebSocket。千问密钥保存在 Netlify 后台，网页不接收密钥。首次使用输入访问码；同一浏览器通常 30 天内可直接继续使用，退出设备或更换后台密钥/访问码后需要重新验证。视频采用低帧率媒体轨道，而不是原来本地版的 JPEG WebSocket 上传；观察时间仍受页面与连接控制限制。

在 Netlify 的 Environment variables 中配置 `DASHSCOPE_API_KEY`、`DASHSCOPE_WORKSPACE_ID`、`DASHSCOPE_REGION`（`beijing` 或 `singapore`）及 `APP_ACCESS_CODE`（至少 8 位）。将密钥与访问码标为 Contains secret values；不要放入源码、网页或配置文件。变更后重新部署，让函数读取最新值。缺少后台配置或访问授权时不会调用千问。访问授权使用加密签名的 HttpOnly、Secure、SameSite Cookie，浏览器刷新不会再次要求填写 API Key。

物品记忆保存在当前浏览器，不与电脑 SQLite 数据库同步，也不与其他访问者共享。只有查询时才把相关记录提供给千问；保存和删除仍需确认。iPhone 使用 Safari 打开 Netlify 的 HTTPS 地址后，无须安装本地测试证书。

```bash
node scripts/build-netlify.mjs
node --test tests/web.test.mjs
```

浏览器媒体权限、网络到千问的连通性及模型准确度仍须实际设备验证。Netlify 和百炼的用量及额度以各自控制台为准。

## GitHub 与其他托管方式

GitHub 仓库用于保存和分享程序。GitHub Pages 只能托管静态网页，不能运行本项目的 Python 后端和实时语音转发服务，因此仅上传代码不会得到完整可用的在线语音视频产品。

原始 Python 后端如需部署到其他平台，需要支持 HTTPS、WebSocket 和访问保护的服务器；不能直接把本机测试服务公开到互联网。上述 Netlify 适配采用不同的连接方式，密钥只留在后台，每位访问者的记忆保存在各自浏览器中。

仓库不包含真实 API Key、个人物品记录、私人截图、访问码或本地服务器证书。

参考：[千问实时音视频接口](https://help.aliyun.com/zh/model-studio/realtime)、[Apple 本地证书信任说明](https://support.apple.com/zh-cn/102390)。
