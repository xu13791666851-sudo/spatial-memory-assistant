# 空间记忆助手：软硬件与无障碍交互方案

日期：2026年10月19日。以下为产品方案及本轮实施范围。根据用户最新要求修订为同一个系统、同一个首页，不设置全盲/低视力或语音/画面模式切换。


## 本轮已接入测试版4

统一首页保留真实手机摄像头、当前任务、最新回答和固定控制。记录按需展开，包含左侧小忆/右侧用户的对话气泡和物品记忆；支持搜索、选择继续找、修改名称/外观/位置、删除确认、语音打开记录、放大收起画面、口头确认或取消待办。沿用测试版4的真实千问接口、现有找物流程和原浏览器存储键，未加入原型里的示例照片或虚构设备电量。观察默认5分钟，可选10分钟，本轮语音上限15分钟。

硬件连接与电量、锁屏后台运行、跨设备同步、持续跟踪、视障用户真机验收仍属后续工作。当前页面离开前台仍会关闭设备；暂停会关闭麦克风，需要点继续恢复，不能声称暂停后还能靠原麦克风听到唤醒。不同测试网址的浏览器数据仍不共享。

## 建议：一个首页，语音与触控始终同时可用

不设置人群分类入口，也不要求用户先选择使用模式。所有用户进入相同首页，使用相同记录、识别结果和任务进度。每项核心操作都能通过语音完成，也有可被读屏操作的屏幕入口；有视觉需求的用户直接展开画面、文字或记录。

全盲用户也需要回顾历史、管理记录和调整设置，可以通过语音与读屏完成；低视力用户也可能在某些时候完全依赖声音。视觉排版可以更简洁，但按钮顺序、读屏名称、反馈和退出方式仍然重要。

| 同一项功能 | 语音操作 | 屏幕操作 |
| --- | --- | --- |
| 找物 | “帮我找水杯” | 可输入同一句话，或选择已保存物品后查找 |
| 查看画面 | “放大画面”“收起画面” | 明确的放大、恢复按钮，支持缩放 |
| 查看历史 | “刚才说了什么”“读一下上一条” | 点击记录，查看或重听任意一条 |
| 记住与纠错 | “记住现在的位置”“这条位置不对” | 打开对应物品，查看、修改并保存 |
| 暂停与恢复 | “停一下”“继续” | 固定位置的暂停/继续按钮；硬件具备按键时提供对应控制 |

自由度来自对当前内容的直接操作，不来自切换整个系统。允许记住文字大小与画面展开偏好，核心控制的位置保持稳定。不根据是否开了读屏猜测用户的视力，也不擅自改变布局。

## 手机首页怎么安排

所有用户共用的首页建议按这个顺序组织：

1. 顶部：设备连接和电量状态；清楚标注当前使用手机摄像头还是硬件摄像头；保留“记录”入口。
2. 中间：适中大小的摄像头预览，可直接放大或收起。硬件不支持实时预览时，显示最近画面及拍摄时间，不把旧截图伪装成实时画面。放大时有明确的恢复入口，无需只靠手势。
3. 画面下：最新一句回答和当前任务，例如“正在找蓝色水杯”。不在首页铺开整段聊天。
4. 底部：开始/暂停或继续、重听、结束。任务中暂停和结束必须容易找到。

“已连接、正在听、正在看、已暂停、需要你回答”等状态同时显示并按需简短播报。普通进度不反复打断，错误和需要回答时必须有明确声音反馈。硬件具备振动时再增加振动，不能假定已购买设备支持。

“记录”从当前首页底部展开，需要时可拉至全屏；关闭后回到原来的任务和画面。内部设置“对话”和“物品记忆”两个页签，不必退出当前会话。平板或桌面可以使用侧栏。

- 对话：按时间查看、搜索、逐条重听、删除，可先听一段摘要。
- 物品记忆：查看名称、外观、多个位置关系、记录时间；区分当时记录与刚刚看到；能修正或删除。
- 两类记录都必须能通过语音访问，例如“我们刚才说到哪了”“我记过哪些物品”。
- 打开历史时不自动朗读全部历史，不让新回复抢走正在阅读的位置。选择旧对话不能悄悄替换当前任务。
- 展开记录时，读屏从记录标题开始，关闭后回到原入口。暂停与结束仍有明确入口。查看旧内容不触发新的拍摄或覆盖正在找的目标。
- 从语音转为点按、输入文字或查看历史时，沿用同一个任务。例如先说“找水杯”，再打开记忆选择“蓝色马克杯”，助手继续寻找该物品，无需重新开始。
- 更高自由度的操作集中在相应对象附近：画面可以放大，回答可以重听或展开全文，物品可以改名和补充关系。物品尚未被可靠定位时，不提供看似准确的点击识别框；该能力应单独验证。

文字大小、颜色和对比度支持调整。按钮不依赖图标猜意思，状态不只用颜色表达；读屏与助手声音需要避免同时抢着播报。

## 手机、硬件和助手分别负责什么

| 部分 | 建议职责 |
| --- | --- |
| 硬件 | 拍摄、采集声音、播放回答；根据真实部件能力提供实体按键或振动 |
| 手机 | 初次连接、联网、设置、查看记录、显示状态和必要时接管；也可独立使用手机摄像头 |
| 助手 | 理解目标、查相关记忆、选择下一步、调用拍摄和识别、保留找物目标、组织回答 |
| 记忆存储 | 先明确记录归属和稳定保存位置，再支持手机与硬件读取同一份数据 |

硬件没有储存卡，不妨碍把文字记忆放在手机或服务端。是否能独立联网、同时拍照和通话、缓存断网数据，取决于实际硬件型号与部件，当前不能据此承诺。

需要区分两种连接路线：

- 手机作为连接中介：硬件把声音和画面交给手机，再由手机连接服务。若目标是手机锁屏后仍可用，需要评估手机应用及相应系统能力；做成应用也仍需真机验证。
- 硬件独立连接服务：手机只负责配置、管理和查看记录。手机关闭后能否继续工作，取决于硬件能否独立联网并完成音视频处理和播放。

早期可在同一网络、手机网页前台的条件下演示硬件拍照。随后根据购买的设备验证两条路线，避免先把产品承诺建立在未知能力上。

## 助手应该怎样主动完成任务

主动性应围绕用户当前交给它的目标。用户说“帮我找蓝色水杯”后，助手应持续保留这个目标，直到找到、用户取消或无法继续。

建议流程：理解目标 → 读取相关历史线索 → 获取新画面 → 判断是否足够清楚 → 选择继续观察或询问 → 找到或明确说明限制 → 结束任务。

示例：

> 用户：帮我找蓝色水杯。
>
> 助手：上次记在书桌电脑左侧，我先看一下现在的画面。
>
> 助手：目前只拍到了电脑右侧，左侧还没入镜。请把镜头稍向左转。
>
> 用户：这样呢？
>
> 助手：现在看到一个蓝色带把手的杯子，在电脑左侧、台灯旁边。这是你要找的吗？
>
> 用户：对。
>
> 助手：找到了，在电脑左侧、台灯旁边。

这些是产品目标，不代表当前已具备稳定的自动连续观察。后续可在找物任务中，检测到画面稳定变化后再取新画面；没有新信息时不重复识别或一直追问。第一阶段只做围绕可见参照物的拍摄引导，身体方向与硬件摄像头方向是否一致需要单独验证。

可以由助手自动完成：选择识别步骤、查询相关记忆、在当前任务内重新拍摄、保留目标、报告进度。需要询问：多个物品无法区分、需要用户移动镜头但方向不明确、要主动覆盖旧记忆。用户明确说“记住这个杯子现在的位置”，且目标与关系足够明确时，可以保存并读回，不必每次增加第二次确认。不能把用户沉默当作确认。

用户说“停一下”“取消”“继续”“你现在在做什么”时，助手要有稳定行为；取消后停止尚未完成的拍摄与保存。断线、相机未就绪或识别失败时，告知发生了什么和下一步，而不是无声等待。

## 保留聊天不等于建立记忆

需要同时设计三个层面：

1. 对话文字供用户回看、重听和删除。
2. 当前任务摘要保存正在找什么、看过哪里、下一步做什么，让“这样呢”“那边呢”能接得上。
3. 物品记录保存用户确认或明确要求记住的名称、外观、位置关系、时间和来源。

不把每句猜测都保存为事实，也不把全部历史聊天反复塞给模型。重新开始对话时，读取与当前问题有关的记录，并明确历史位置尚未被当前画面确认。

当前预览网址之间的浏览器记录互不共享。后续应使用稳定入口，制定记录迁移方式；如需跨设备，再设计用户身份与同步，不能继续只依赖某个临时预览网址里的浏览器数据。

## 建议的推进顺序与验收

第一步：以测试版4为当前基础，核对与测试版3的功能差异；首页保留画面、最新回答和主要控制，把完整历史收进记录页。先保留现有可用对话能力。

第二步：让“记住—查询—继续找—纠错—取消”都能纯语音完成，并检验随时改用点按、输入或展开内容时，任务与结果保持一致。优先做好一个家中找物流程。

第三步：接入硬件画面和声音，验证实体控制、断线恢复、电量提示及手机后台/锁屏。确定实际能够支持的手机依赖程度。

第四步：分别邀请全盲和不同低视力情况的真实用户试用。开发者闭眼操作可做早期检查，但不能代替真实用户的读屏和使用习惯。

验收关注任务能否完成，而不是只看界面是否简洁：能独立启动和停止；能在不看屏幕的情况下找回一件物品；能修正错误记忆；模糊或未找到时有明确反馈；刷新或重新连接后历史仍可查询；放大文字不裁切主要控制；助手声音不和读屏互相覆盖。
