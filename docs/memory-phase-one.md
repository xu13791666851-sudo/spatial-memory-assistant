# 第一阶段：结构化意图与会话观察

2026-10-29 实施。适用范围：`demo/` 完整网页后台，以及连接它的 iOS 测试工程。尚未改造基础 Cloudflare 网页、安卓本机核心或线上部署。

## 已实现

- `demo/intents.py`：版本 1 的结构化意图，分别保存动作、物品指代、时间范围和澄清问题。拒绝未知字段、越权用户字段和矛盾的动作/时间组合。
- 固定口令先走确定性规则。取消、关闭摄像头、拿到了不依赖模型。自由说法通过千问文本请求返回 JSON，再由 Pydantic 和程序规则校验。
- 使用现有服务密钥，默认意图模型为 `qwen3.8-omni-flash`；可通过服务器环境变量 `QWEN_INTENT_MODEL` 覆盖。真实网关须支持 JSON Object 格式，失败时明确澄清并保留固定口令，不自动降级成写记忆。
- “上次记住的蓝色水杯现在在哪”解析为历史物品引用＋当前寻找；“蓝色水杯上次放在哪里”解析为历史查询；“我想把这个杯子记下来”进入采样记忆流程。
- 模型不能将“可能在厨房”等临时陈述直接升级成记忆写入。否定/引用语句不授权写入。位置更新暂时引导用户通过记录编辑，避免对旧目标错误重新采样。
- 意图请求与命令修订号绑定：取消、停止或更新命令后的旧模型返回不再执行。
- `demo/working_memory.py`：每个会话独立保存最新画面、检出对象、采集时间、场景修订号和最近一次成功描述；不保存到长期数据库。
- 当前描述必须获取本次请求之后的新帧，检查图片采集时间和处理后存活时间；默认有效期 3 秒、未来时间偏差容忍 1 秒。该阈值是第一版工程设置，需真机测延迟再调整，不是识别准确性保证。
- 当前描述不再附带全部长期记录。图像分析结果及找物复核返回时再次检查时效，过期就报告未确认，而不作为当前事实播报。
- “刚才看到的是什么”回顾最近一次成功的本轮画面描述，带采集时间并说明不代表现在仍可见。不是查询任意过去帧或按物品筛选的完整视觉历史。
- 停止或暂停清理短期观察；显式切场景使当前证据失效。长期物品库继续原样存储在 SQLite 中。
- 历史查询返回记录时间及历史来源，不启动视觉推理。完整网页未开始时，文字输入可以直接查询历史；需要当前画面的命令会提示先点击开始，不自动索取媒体权限。
- 网页端收到后台停止状态也会主动停止本地相机、麦克风与播放，避免页面只改状态、设备仍在采集。
- 状态接口新增 `intent` 与 `shortTerm` 元数据，不公开图片或密钥；原有 `state`、`memories`、事件格式保留。
- 完整网页构建不再要求复制无用的浏览器 TensorFlow 模型运行时；基础网页和安卓构建仍走原有默认流程。

## 运行与测试

需要 Python 3.11+、Node.js 22+。本次 Windows 环境在项目 `.venv` 使用 Python 3.12，安装测试所需 FastAPI、httpx、websockets，复用运行时已有 NumPy/Pillow/Pydantic；没有安装或运行真实 LiteRT 检测器，也未读取实际用户密钥。

```powershell
# 项目根目录是 05_项目源码
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "*test.py" -v
node --test tests/demo-bridge.test.mjs tests/realtime-observation.test.mjs tests/conversation.test.mjs tests/target-overlay.test.mjs tests/yolo.test.mjs
node scripts/build-demo.mjs
```

正常部署继续使用 `demo/requirements.txt`。`npm run test:demo` 现在覆盖新的 Python 测试与网页桥接测试；Mac/Linux 请先激活适当的 Python 环境。iOS 调整后端即可使用这些能力，无须重写客户端。

自动测试使用替代视觉/云端回复。覆盖原有保存与隔离、新旧时间分流、自然记忆口令、模型意图适配器请求格式、非法结构和写入拒绝、取消竞态、新帧要求、过期描述及过期找物复核、短期回顾、只读历史、会话清理、网页媒体停止等。Node 桥接测试使用虚拟设备与网络，不能代表 Safari/WKWebView 真机权限效果。

本轮实际结果：29 项 Python 测试、29 项 Node 测试全部通过，完整网页构建通过。其中 Python 包含原有 9 项和新增 20 项；Node 包含 2 项新桥接检查及 27 项现有相关回归。没有执行需要真实千问、模型服务和浏览器媒体输入的完整浏览器验收脚本。

真实千问接口、iPhone 的音频/相机、ESP32、Xcode 编译、真实模型准确率本轮未验收。网页前端未开始时要求手动开始当前观察，这与旧版输入即自动启动媒体的行为不同。

## 尚待继续

1. 人工测试已有网关的 JSON Object 支持和真实表达识别效果，记录意图正确率、误写入率、延迟。解析格式正确不等于理解正确。
2. 自动镜头/场景变化判断、持续目标跟踪、多个相似物体消歧仍需补强；目前显式切场景及超时失效不等于完整空间追踪。
3. 当前短期层只有最新帧与最近描述，不包含全部观察事件，也不跨会话恢复。长期库尚未增加位置事件历史；同名物品覆盖、样本质量和安卓安全写入问题仍按总方案推进。
4. 下一阶段将物品身份和位置事件分开建模，并提供一致性导出、备份及存储仓储接口，然后接入 Supabase Auth、Postgres 和私有 Storage。
5. Supabase 尚未连接、未迁移任何用户数据；不需要把管理密钥填入手机。
