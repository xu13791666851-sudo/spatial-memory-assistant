## 失败原因的证据边界

截图那一轮没有记录分项错误，无法追溯认定是网络、服务返回异常或模型输出格式错误。已确认旧程序将这些错误统称“连接慢”；电脑图片请求10秒就停止，而中转服务可等待上游12秒；Jev可等待8秒，但找物结果超过3秒就被静默丢弃。这些是不同的失败来源，不能据此认为水杯不在画面中或记忆已丢失。

现已分类记录处理阶段、错误类别、画面编号和耗时，不记录现场图片、对话、语音或密钥。图片请求给中转12秒等待另留3秒传输时间。过期对比结果只能作为刚才的观察反馈，不能用于宣称当前已找到。

## 当前找物流程

查询最后位置：名称与已有别称匹配 → 同一物品编号 → 读取位置、来源和时间。无需打开摄像头，也无需重新看图。

确认当前位置：新画面 → YOLO筛出目标类别并裁剪候选 → 有已保存外观特征时按粗略颜色相似度排序，否则按类别置信度排序 → 当前候选裁图与已保存参考照片交给Jev → 核对是否为同一件 → 检查画面时效后回答。Jev排除的候选会让位给其他候选；未检测到候选不等于确定不在。粗略颜色相似度和YOLO类别分数都不是身份确认分数。

Supabase仍负责私有备份和恢复；对比用的是电脑本地已保存或已从备份恢复的照片，不是每次远程下载。没有参考照片时会明确说明，不能仅凭“都是蓝色杯子”确认属于同一件物品。

“蓝色水杯”现在能对应cup类别，“杯子／水杯／我的水杯”等叫法可关联；多件相近物品仍保留各自编号，需要选择，不自动合并。当前讨论的物品在追问和失败后继续保留，新会话才清除临时指代。截图中的追问已纳入检查。

记忆反馈区分当时画面观察和已核对位置；查询和找物不自动改写位置记录。
