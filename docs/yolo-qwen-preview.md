## 接入范围

保留现有页面布局、按钮、场景选择、语音、记录和物品记忆界面；按新增需求，仅在摄像头画面上叠加当前记忆目标的识别框。移植交接包的模型预处理、识别结果解析、同类别框去重、中文目标映射和稳定候选规则，不把 Android 页面或调试界面搬进网页，也不复制包内的密钥。

交接说明写“141 类”，但实测标签数为 **80**，模型输出为 `[1,84,8400]`，输入为 `[1,3,640,640]` 的浮点 RGB 数据。钥匙、耳机等无对应类别的物品继续由千问识别，不能把 YOLO 没检测到当成物品不存在。

## 实际流程

1. 开启摄像头后在后台预加载原始 TFLite 模型；首页不会等待模型下载才显示。
2. 具名找物时，支持的类别先在独立 Worker 中识别两张新画面。候选分数至少 0.5，同类框重叠比例至少 0.2，且每张画面中该类别只有一件候选，才算稳定。YOLO 类别只表示“杯子”，不表示“已记住的那只绿色水杯”。
3. 将最后一张本地检查过的完整画面与其候选区域的放大图，分别交给千问并行核对。两个请求各自验证画面回执与编号；颜色和历史外观必须相符。裁剪图的左右不用于整图定位，候选区域用原图坐标说明。
4. 恢复两张新画面的连续确认，不再因为 YOLO 稳定就省略第二轮。整图漏看但放大图能确认时，可修正漏检；两幅图结论冲突、外观不同或细节不清时不提示找到。放大请求单独出现网络错误时，保留已经独立验证成功的整图结果，仍需两张新整图外观匹配才能提示找到，不显示确认框。如果整图请求失败、但同一帧的放大图已明确匹配目标外观，只保留放大区域的目标与原图区域坐标，不编造整图背景；仍需第二张新画面确认。两路都失败则暂停观察，不能把失败当作没看到或已找到。YOLO 不能单独宣布找到，也不能单独保存或更新记忆。
5. 模型未准备好、不支持某类别、出现多个同类物品、低分、加载失败或设备较慢时，沿用原来的千问路径。本地双帧最多等待 4 秒，超时后本轮会话回退，不反复增加等待。放大复核每轮会发送两个请求，因此自动观察间隔至少 14 秒，以保留后台请求限制。

普通问答、描述环境、询问历史位置、直接看图记住和无名称物品识别沿用队友版本；YOLO 参与具名找物与近景复核。暂停、取消、切换场景、关闭相机、结束会话时，旧识别结果不能继续提交、保存或提示找到。

“重新帮我找绿色水杯”“再帮我找这个杯子”等重试说法现在进入同一个找物流程；明确再次寻找时会读取匹配的本机记录，提示实际读到了什么，以及是否有保存的外观。“我已经把镜头对准绿色水杯了”等近景反馈保留同一目标和外观。原有寻找状态栏会说明 YOLO 正在加载、已检出候选、正在放大核对或已回退；不新增页面或改变布局。Cloudflare 的带编号预览网址也可启用 YOLO。

不同网址仍有独立的本机记忆。正式站里保存过的记录不会自动出现在测试站，不能因此断言原记录丢失。回执和重新寻找都会依据实际保存、实际读取的结果，不能把模型说“记住了”当作浏览器已经写入的证据。

## 记忆目标识别框

只显示当前正在寻找、且本轮确实读取到唯一已保存记录的目标。其他检测出的电脑、书、杯子不画框，也不把同类物品都标成用户自己的物品。

- 蓝色虚线及“待核对”：YOLO 连续两帧检出的类别候选，尚未完成最终确认。
- 绿色实线及“外观已核对”：已保存外观与放大图的千问结果相符；自动寻找还需两张新画面确认。没有历史外观或放大请求失败时不显示确认框。
- 框按原始视频坐标定位，补偿横竖画面留白，随放大/收起调整，不阻挡点击。
- 只对应最近分析的那一帧，最长 8 秒；每 160 毫秒在本机比较整图及目标区域的小图，镜头或目标明显移动就立即撤框，回到旧角度也不恢复旧框。暂停、取消、换目标、换场景、停止摄像头，或对应记录被编辑、删除时撤框。不把它表述为持续的物体追踪或身份识别。

## 运行与发布

```sh
npm ci
npm run build:cloudflare
node --test tests/*.test.mjs
npm run test:yolo:browser
npm run deploy:yolo-preview
```

浏览器检查沿用仓库的 Playwright 依赖方式，可用 `PLAYWRIGHT_MODULE` 指向已安装的 Playwright。

合并主分支后，根目录的 `wrangler.jsonc` 仍指向正式 Worker `i-see-you-spatial-memory`；测试 Worker `i-see-you-yolo-preview` 使用独立的 `wrangler.yolo-preview.jsonc`，`npm run deploy:yolo-preview` 会显式选择它。Pages 配置在 `cloudflare/yolo-pages/wrangler.jsonc`。测试站通过私有服务连接调用现有后台，运行时密钥不用重新复制。测试请求会使用同一个千问账号和原有请求频率额度。

首次创建同名 Pages 项目，生产分支填 `main`，生产及预览环境的 `MEMORY_API` 绑定到测试 Worker。发布命令只部署测试 Worker 和此测试 Pages 项目，不合并主分支。

模型原始大小为 38,073,903 字节，以 5 个文件分片保存，加载时逐片核对 SHA-256 并在内存中还原。每片小于 Cloudflare 的单文件限制；有版本标识的模型分片和依赖可缓存，普通网页和识别接口不缓存。

测试站为本地识别启用跨来源隔离，浏览器支持时使用最多 4 个计算线程。TensorFlow 运行库需要的动态代码许可仅放在无 DOM 的检测 Worker 响应上；页面本身不允许 `unsafe-eval`。所有运行库和模型从本站加载。

## 已验证与限制

真实浏览器已加载并执行交接包模型，在现有桌面测试图中检出水杯、电脑、书和盆栽。电脑本地 4 线程运行约 0.6～0.75 秒/帧；上线后复测约 0.8～1.2 秒/帧，稳定双帧约 2.02 秒。千问对最后一张本地检查过的图片返回了清晰画面回执、目标可见及水杯的相对位置，样例请求耗时约 4.6 秒。这些是开发电脑的样例测试，不代表手机性能或整体识别准确率。单线程样例约 1.7 秒/帧，会走速度较慢的回退分支。

181 项自动检查通过；原有 9 组页面浏览器检查已通过，本次另复测连续找物与统一首页，并新增真实视频画面的框位置、三种屏幕尺寸、放大收起、点击穿透、镜头移动与过期撤框检查。三个生成 HTML 保留原结构，新增样式只作用于目标框。线上真实语音连接成功，收到“你好”的回答与音频轨道；测试页在 390px 宽度下无横向溢出。首次无缓存模型加载样例约 54 秒，等待期间继续使用原千问流程。真实手机速度尚未验收。

首次下载模型需要流量和时间。手机浏览器、网络、散热和内存条件不同，不能保证一定快于纯千问。错误类别、低光、遮挡、多件相似物品等仍可能识别失败，最终提示受千问确认与现有证据校验约束。未将此实验合并到主分支。

本次线上实测：整图正常返回蓝色水杯及其外观；寻找绿色水杯时，整图与真实 YOLO 候选放大图均返回颜色不符。也实际遇到千问超时及未完成的返回，因此未宣称云端稳定性或真实手机准确率已完全解决。失败时使用上述回退或暂停机制。
