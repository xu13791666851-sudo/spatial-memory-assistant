# 第二轮：独立图片复核与物品记忆修复

更新：2026-11-01。版本：`0.6.1-tablet-memory`（版本号 8）。

## 现在的工作方式

平板相机负责提供画面，本地识别负责找出疑似目标，独立图片服务负责对照照片复核。语音和文字都能发起任务；语音断线不会中断图片请求。找物的确认和播报由应用统一处理，语音模型自行说“看到了”不算图片确认。

对于已经记住的物品，复核会使用当前全景、当前候选与这件物品的参考照片。现有网关支持两张输入图，因此候选和最多三张参考被排成带标签的对比图，参考不会被当作当前画面。

语音模式仍需联网。物品资料和位置历史存放在平板本地；本轮没有接入 Supabase 或 Jev，也没有改动 ESP32 固件。独立复核接口为后续接入其他视觉服务保留了位置。

## 怎么使用

- 新增物品：说或输入“记住水杯”，按提示把它放在中央并转动，采集不同角度。三张照片经过复核且全部保存成功后，才会提示“已经记住”。再次这样操作会新增另一件，不自动覆盖同名物品。
- 更新已有物品：打开“对话记录 → 物品记忆”，在正确的那条记录上点“更新这件的外观”。更新成功前保留旧照片，更新后保留该物品原有的位置历史。
- 找指定物品：在列表点“找这件”，或说“帮我找水杯”。有多件同名物品时，先在列表选择，或说“第一件”“第二件”。选择后按具体物品继续操作。
- 添加自己提供的位置：输入“记住，水杯放在书桌”。它会作为“你提供的位置，未经相机核实”追加，不抹掉之前的记录。“可能在书桌”仅是线索，不写入位置历史。
- 让相机记录位置：说“记住水杯的位置”。应用先寻找并复核，确认后追加当时的位置；未确认不写入。
- 查询过去：说“水杯上次在哪里”，或点物品的“位置历史”。记录时间和来源会一起显示。查询历史可以不开相机、不联网；历史不代表物品现在仍在那里。
- 使用文字：在“对话记录”的输入框发指令。文字找物只申请相机，不开启麦克风；查询历史不会开启相机。输入后可点“回到首页”看实时画面。

## 保存与旧记录保护

同名物品使用不同身份保存。更新、删除、寻找和位置历史都指向选定的那一件，不再按名称删除或覆盖。

照片先写入新批次并校验，再一起提交物品与照片记录。中途失败或取消时，新批次会清理，原记录和原照片不受影响。更新外观不删除原物品，也不连带删除它的位置历史。

数据库从版本 2 升级到 3。首次升级前，在应用自己的目录制作并校验旧数据库备份；升级整体失败会回滚，不清空重建。旧版仅按名称保存的位置，在允许同名之前完成一次归属转换。旧表保留归档，后续读取不再按名称回查旧位置。

用户编辑的时间与实际观察时间分开。旧版无法区分的时间保留为记录时间，观察时间显示未知；不会把旧记录或人工编辑伪装成刚刚被相机看见。

## 本轮验证及范围

检查日志和安装包位于 `output/android-memory-2026-10-31/`。最终通过 55 项单元检查、应用检查、签名校验及 18 项模拟器检查。模拟器检查覆盖真实 SQLite 升级、磁盘写入失败、数据库提交失败、取消时回滚、同名隔离、外观更新保留历史、旧窗口编辑冲突，以及断线、迟到、画面变化、视频中断和文字模式不恢复麦克风。

真实图片服务已用项目自带的公开公交车测试照片独立调用成功，没有创建实时语音会话；首次约 7 秒，最终复测约 9.8 秒。模拟器默认解析外网域名失败，联网检查临时使用电脑解析出的服务地址，仍验证原域名的证书。这只影响测试助手，实际应用与平板网络设置均未修改。

据实测延迟，图片最多等待 15 秒；用于确认的原图最多 12 秒，同时要求最新视频帧在 2 秒内、视频仍运行、任务与物品版本未变、全景和候选区域未明显改变。确认后还继续核对候选区域，变化时撤回引导。请在复核时保持画面稳定。这些检查用于拒绝明显过期的结果，不能证明两件外观完全相同的实物身份。

实体 Pad 5 仅更新 `com.spatialmemory.assistant.iseeyou.tablettest.debug`，没有安装自动测试助手。升级前后原有三条对话逐字保留，数据库实际升级已检查，旧版自动备份已检查，相机和麦克风均在检查结束后停止。实体平板原本没有已保存物品；带照片和位置的迁移验证在专用模拟器的独立测试数据库完成，不能写成真机已有物品迁移。

私有备份和截图只留在开发副本的忽略目录中，不进入源码提交，也不加入交付文件。没有读取或删除其他应用的私人数据，也没有删除平板原有照片与文件。

## 下一步

用实际的杯子、钥匙等物品建立一组可重复对照：同名不同外观、同色不同物品、遮挡、光线变化、移动过程中取消。统计找对、找错、不确定与等待时间，再调整图片复核和本地筛选。公交车测试只证明服务和数据流跑通，不代表个人物品识别准确率已经达标。完全相同外观的实物需要可见的区分特征。

这之后再比较 Jev 的实际接口、效果和耗时，决定是否接入。云端同步应沿用物品身份，不可再按同名合并记录；ESP32 仍由队友实现约定的视频输入接口。
