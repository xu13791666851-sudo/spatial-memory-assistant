# 语音反馈与识图并行（2026-11-05）

基于 0.17 候选版的源码改动，尚未生成或安装新版 APK。

## 行为

- 相机已由用户开启时，沿用持续上传和本地检测。空闲检测保留最多八个候选裁图；找物请求可直接复用同一来源、同一新鲜帧的检测结果。缓存不会刷新检测时间，也不会作为新的跟踪帧。
- 明确的看图、记忆、找物指令立即启动任务，不等语音播完。120ms 内已有结果则直接回答，否则通过安卓已有 TTS 播放一句“我看一下／我正在记录／我帮你找”。120ms 是服务端意图明确后的提示调度间隔，不是端到端延迟承诺。
- 提示语不宣称已经保存或找到。正式结果、失败说明优先替换提示语，包括 TTS 尚未初始化时的待播队列。提示语不会抑制随后的错误反馈。
- 历史位置、是否记住和外观查询继续直接读记录，不额外调用视觉。查询正在保存的进度不会中断保存。
- 新视觉任务会中断旧视觉请求；停止、新会话清除待发提示。客户端在发出新指令时立即清空旧播报，并用 commandId 拒收旧任务回复。附和词不会替换正在执行的任务。
- 已保存的场景和历史数据保留。取消尚未完成的分析后，不把迟到的识别结果补写成新记忆。

## 测量口径

电脑 diagnostics.jsonl 分别记录 ack_ready、progress_ready、result_ready，起点是电脑收到指令，终点是发出相应事件。result_ready 包括有效回答、无法确认及失败说明，不代表成功找到物品。

新版安卓通过 TTS onStart 在 Logcat 的 PcTurnLatency 中记录 ack / progress / result 实际开始播报的耗时；起点是收到完整转写或提交文字指令。该值不含用户语音终点到完整转写之间的等待，也不能代替扬声器物理出声的测量。现场端到端验收仍须从用户最后一个音节到有效回答出声计时，同时记录找回成功率、误认率和 P50/P95。

仍沿用现有 TTS 播报期间暂停麦克风的回声防护；本次实现语音反馈与视觉并行，不包含播报中持续收音的全双工改造。已接收到的新指令以及界面取消均会作废旧任务。

## 应用更新

源码更新包按仓库相对路径包含本轮修改，覆盖到相同 0.17 基础源码后，在原安卓开发环境构建并安装新 APK，更新电脑源码并重启电脑服务。电脑和平板两端都更新后，才能获得结果替换提示语和 commandId 过滤的完整效果。旧 APK 不理解新增的播报优先级，不能用于验证完整行为。

不覆盖 runtime、个人记忆、照片、模型、配对信息或密钥。本包没有 APK，也不是独立完整项目。

现场至少测试：快速回答、慢响应、说完后改找另一件、界面取消、记忆分析失败、只问历史位置、断网恢复和重启后记忆仍在。结果必须对应当前任务及有效画面，提示语不能被统计为成功结果。
