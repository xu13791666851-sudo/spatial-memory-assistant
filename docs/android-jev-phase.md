# 千问与 Jev 分工接入记录

日期：2026-11-01。开发候选版：0.7.0-tablet-jev；平板可用版仍为 0.6.1-tablet-memory。候选版尚未通过云端联网验收，不覆盖平板。

## 模型分工

千问和 Jev 同时存在。千问保留实时语音、用户语音转写和每秒最多一帧的低频全景理解。安卓本地 YOLO 提供疑似物品，Jev 接收当前全景、候选裁剪与最多三张历史参考照片，判断目标是否可见、照片是否清楚、是否为同一个物品。统一找物核心继续核对任务、视频源、画面新鲜度和物品版本，决定是否确认与播报。

正在找物时，应用统一播报优先，千问自己描述“看到了”不作为找物确认。文字模式只使用相机和独立图片复核，不开启实时语音或麦克风。千问原有独立图片复核代码保留用于开发对照；生产找物流程没有自动切换两家，也没有因 Jev 失败而把千问的对话当作图片证据。

本轮没有新增 Supabase 或 ESP32 固件。Supabase 的后续工作先做账号、私有照片、备份与恢复，再做多设备同步。

## 已完成的接入

- 安卓新增 Jev 图片客户端，主界面与硬件调试入口的开发候选版使用它；千问的对话连接保持原实现。
- 新增 `/api/android/review`。后台固定向 TypeSafe 官方 `/v1/systemone` 调用 `jev-1.14.0`，图片实验开关随请求发送；客户端不能指定任意服务地址、模型或问题。
- 当前图和历史参考分别提交，不把历史图当作当前事实。小图补边到官方最小尺寸，先转正像素，过大的图片按比例缩小。
- 使用 Noul 概率分别判断可见性、细节和身份。强确认要求可见性至少 0.9、清楚度至少 0.8，个人身份至少 0.9；这些是待真实物品校准的工程初值。中间值、缺字段、非法概率和矛盾结果不能确认。
- 取消操作关闭实际 HTTP 请求，返回结果必须对应原任务、候选和帧。既有画面变化与过期保护继续由找物核心负责。
- 密钥由服务端加密配置保存；本机额外副本使用 Windows 当前用户加密保护。源码、安卓安装包和交付报告中不保存密钥。后台只返回经过筛选的结果，不返回上游原文或凭证。

## 验证结果与当前阻塞

55 项安卓基础检查、静态检查、签名检查通过；14 项服务端检查通过。模拟器一轮共 24 项：23 项本地检查通过，1 项真实联网检查失败。失败项不是准确率失败，而是网关调用 TypeSafe 时收到 HTTP 451，原文为 `Typesafe is not available in your region.`。不能将这轮写成 24 项全部通过。

密钥的文字验证成功。电脑沿用原有系统网络路径，公开公交车图片和参考照片的真实调用也成功，约 7.1 秒；返回模型为 `jev-1.14.0`。后来核对发现 Python 会使用电脑原有的系统代理，而 Node 与云端直连路径收到地区不可用。因此电脑成功不能代表云端或平板已经可用，未修改电脑或平板代理、VPN、DNS 等设置。

Cloudflare 网关新增路由已部署，原千问临时凭证仍能实际获取；这里只记录成功与否，不记录凭证。曾按 Cloudflare 官方 Placement 配置尝试美国东部后端位置，仍收到 451，随后撤销该配置。没有通过伪造请求来源、转交密钥给未知转发商等方式继续尝试。

目前 `/api/android/review` 将上游地区限制明确报告为服务暂不可用，不能返回“已找到”。需要 TypeSafe 确认该账号允许的服务器地区或官方接入方式后，再完成真实联网检查和更新平板。该情况不影响 0.6.1 平板现有的千问图片复核。

## 平板与数据保护

只核对并备份本项目独立测试版自己的数据。平板原有三条对话保持，物品记录原本为零。没有在实体平板安装自动测试助手，没有安装尚未验收的 Jev 候选版，没有操作其他应用、共享照片或文件。
