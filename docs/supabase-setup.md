# Supabase 一次性准备

项目：`awkzcvvzrsfjvqlloqqi`。本功能把应用的物品记忆快照保存到私有文件空间，安卓本地数据库继续负责日常使用。

## 1. 创建私有备份空间

打开 https://supabase.com/dashboard/project/awkzcvvzrsfjvqlloqqi/sql/new 。

将 [备份准备脚本](../supabase/migrations/202611010001_memory_backups.sql) 的全部内容粘贴到 SQL Editor，点击 Run。成功后应看到：

- `iseeyou-memory-backups`，`public` 为 `false`。
- 两条规则：`iseeyou_backup_insert_own`、`iseeyou_backup_read_own`。

脚本只创建本项目私有备份空间和规则，不删除数据，不开放公开访问。每个登录账号只能读取和新增自己目录中的备份，应用没有覆盖或删除云端备份的权限。

## 2. 默认登录邮件即可使用

默认发信服务会锁定模板，页面提示需要自定义 SMTP 后才能编辑；这不是 Source/Preview 选项的问题。0.8.1 起应用支持直接验证默认邮件中的登录链接，因此无需为了开发测试先修改模板或配置新的发信服务。

在邮件中复制登录按钮的原始链接地址，不要先点击消耗链接。在应用已有的对话输入中输入 `登录链接 链接地址`。应用只把一次性验证信息提交给本项目固定的 Supabase 地址，不会打开链接中的跳转地址，也不会把链接写入对话记录或发给千问。

如果以后自行配置了 SMTP 并希望使用数字验证码，可在 Magic Link、Confirm Signup 邮件模板中包含：

```html
<h2>I SEE YOU 登录验证码</h2>
<p>你的验证码是：{{ .Token }}</p>
<p>如果不是你发起的登录，请忽略这封邮件。</p>
```

保留邮箱确认功能。不要将整个应用设成公开读写。[Supabase 默认邮件服务](https://supabase.com/docs/guides/auth/auth-smtp) 只向项目组织团队成员的邮箱发送邮件，当前默认额度为每小时两封；普通应用用户的邮箱需要自行配置发信服务。是否能够收到与“会员”不是一回事，应用会保留实际失败原因，不会据此宣称登录成功。

## 3. 应用内使用

不增加首页按钮或图片复核设置页。在已有“对话记录”的输入框中输入：

1. `登录备份 你的邮箱`：申请登录。0.8.2 起，本地等待保留一小时；同邮箱仍有有效申请时不会重复发信，使用最近收到且尚未打开的邮件即可。链接是否有效仍由 Supabase 验证。
2. `登录链接 邮件中登录按钮的原始链接`：完成默认邮件登录。如果邮件本身有数字验证码，也可以用 `验证码 收到的数字`。邮箱、登录链接和验证码不会写入对话记录或发给千问。
3. `备份记忆`：立即备份已保存的物品、参考照片和位置历史。
4. `恢复记忆`：读取当前账号最近备份，核对完整性后补回缺失物品。相同物品 ID 的现有记录保留，重复恢复不会重复添加。

只有出现“备份账号已登录”才表示登录完成。“邮件已发送”只是开始等待邮箱验证。如果邮件按钮已经点击、链接被使用或服务端明确报告过期，可发送 `重发备份邮件 你的邮箱`，但发送请求至少间隔 60 秒，并继续遵守项目发信限额。收到发送限额提示时，不要连续申请；应用不会关闭邮箱验证或绕过服务限制。

登录后，本应用运行期间在记忆变化后自动安排备份；离线、关闭应用或上传中断时，本地记录仍保留，再次打开会重试。无需为了恢复而清空平板或卸载应用。

备份不包括 Jev/OpenRouter 密钥、登录令牌、网络配置、当前画面或临时任务。对话记录继续保留在原位置，不在这版物品备份的范围内。单个快照最多 40 MiB；超出限制会明确报错，不会删除本地记录或覆盖已有备份。

## 4. 本轮连接方式

这台平板当前直连 Supabase 请求中断，因此 0.8.1 通过本项目现有的 Cloudflare 服务连接固定的 Supabase 项目。该接口只转发必要的登录和私有备份读写操作；Supabase 仍校验用户身份和文件访问权限。没有修改平板的系统网络设置，也没有将存储空间改为公开。

项目 URL 与 publishable key 是客户端公开配置，不是后台管理员密钥。登录令牌保存在应用加密存储中，照片和位置历史只在登录后的备份操作中上传。
